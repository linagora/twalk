# The user's own messages are their own event type, and the user is not a contact

A message the user sends from their own phone is published as `outbound.message.sent`, a type of its own, with the operator's Matrix ID as the subject and **no `consent` extension at all** — the extension is a contact's decision, and there is no contact here. The user stops being a contact: their network ghosts (`@whatsapp_<login id>`, `@signal_<uuid>`, one localpart template per bridge) are resolved as the operator and never enter the consent model, so there is no consent row on the user that could be set, revoked, or waited on. Which ghosts are the operator's is a fact the deployment resolves from the bridges' own `logins` and `whoami` answers and hands to the Sensor; it is not derived by string-building in the Sensor, because the localpart template belongs to each bridge. A persona is not triggered by this type, enforced in the SDK beside the consent gate.

Rationale: a portal room mirrors a conversation in both directions, and the Sensor had no notion of the operator, so the user's own messages arrived through the inbound door with the user as the subject and `consent: pending` — the system holding that its own operator had never decided about themselves. Observed live in Signal's Note to Self, a conversation with no second party, where a persona would have suggested a reply to nobody. The two alternatives were weighed and rejected. A `direction` field on the existing type keeps the contract at eight types before its v1.0 freeze, which is a real benefit, but leaves `inbound` naming an outgoing message and leaves the user inside the consent model; worse, a consumer that forgets the filter is triggered by the user's own traffic and nothing says so — the failure is silent, and silent gates are what ADR 0013 and the SDK's consent gate exist to prevent. Not publishing them at all is the most conservative reading and was rejected because a persona that cannot see the user has already replied will suggest answers to closed conversations, and "unanswered conversations" becomes unbuildable; the data would be missing for the whole of v0.1 and unrecoverable afterwards. The ninth type is the price of an envelope that does not lie: a consumer that never subscribes to it cannot be surprised by it, which is the property the other two options cannot offer.

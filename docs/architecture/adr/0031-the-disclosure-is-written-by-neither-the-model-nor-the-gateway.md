# The disclosure is written by neither the model nor the Gateway

The sentence [ADR 0019](0019-a-persona-discloses-itself-to-the-contact.md) requires is held **in the SDK, one per language**; the persona **selects** the one matching the language it wrote in, because it is the only component that knows that; it travels as **a field of its own** on `persona.suggest.produced` and `persona.reply.approved`, never inside the body; and the **Companion Gateway appends it** to `final.body` when it publishes the approval. The sentence is *"Drafted with my AI assistant."* — *"Rédigé avec mon assistant IA."* — invariant whether the human sent the suggestion untouched or rewrote it completely, so that it stays true in every case the approval path can produce; it names no product, because it describes the message and not the user's infrastructure; and it says **AI** without euphemism. It goes **after** the message on a line of its own, since a prefix is precisely what a bridge's relay mode does and ADR 0025 rejected that by name. It is identical on every network, including SMS where it may cost a second billed segment, because a disclosure that varies by network is one that can be argued down network by network until nothing is left, and the first argument will always be money. It is removable **only globally**, never from a single message, and the removal is recorded in an append-only journal of its own — a sibling of the consent journal, sharing its triggers and its `occurred_at`/`actor`/`reason` shape, and deliberately **not** the consent journal itself nor the settings table. The approval screen shows the outgoing message whole: the body editable, the disclosure fixed beside it, and **when the switch is off, the screen says so** — a fact stated at the one moment the user is thinking about a particular message going to a particular person. A reply written in a language the SDK's table does not cover produces **no suggestion at all**, with a named and counted reason.

Rationale: three of the four possible homes for the sentence are closed by things already true of this code, and the inventory that established it is the reason this ADR exists rather than a patch. **Not the prompt**, because [#100](https://github.com/linagora/twalk/issues/100) makes a suggestion editable: a sentence inside the body is deleted with one keystroke, and its deletion is indistinguishable from any other edit — the store records `edited: true` and, by deliberate design, not one word of what changed — which is the exact opposite of ADR 0019's requirement that removal be a recorded deliberate act. **Not the Gateway composing it**, because no event in the contract carries a language, neither the Gateway's `Suggestion` nor the Sensor's `ApprovedReply` declares one (and both are deliberately exhaustive: what the struct does not declare, the process does not hold), no component performs language detection, and the only language value the Gateway holds is the user's own preference, which `settings.rs` forbids for outbound text in terms — *"a French user answering an English-speaking contact in French has been handed something they cannot send"*. There is also **no server-side message catalogue in this repository, in any component, in any language**: a Gateway-composed sentence would require inventing one for a legally significant text, maintained in Rust, without the native-speaker review the Companion's catalogues have. **Not the Sensor appending at send**, because three tests in three components assert that what was approved is exactly what goes out — one of them with an `assert_ne!` whose message is *"the persona's own words were replaced, not appended to"* — and because the bus would stop recording what the contact received, which is what makes ADR 0025's accountability argument hold at all. What remains is the shape above, and it is better than a compromise: the model never writes the sentence so it cannot be argued out of it, the human cannot remove it per message because it is not in the field they edit, the Gateway needs no language because it composes nothing, and `edited` keeps its meaning because the comparison is against the body alone. Disclosing once per conversation is not reconsidered here; ADR 0019 rejected it, because *"once" becomes "never" over a long relationship and a contact who joins a group later never sees it*.

The costs are accepted rather than argued away, and the first is an exception to a rule this project wrote for itself. **Two v1 schemas gain an optional member**, although their own descriptions say any breaking change requires a new version suffix — and adding a member to an object closed with `additionalProperties: false` breaks a third-party validator pinned to v1, which `contracts/README.md` invites by publishing the schemas under CC0. This is recorded as a deliberate exception and not as a creative reading of "breaking": the v1.0 freeze is ahead rather than behind, [ADR 0028](0028-a-contacts-words-live-apart-from-the-event-that-identifies-them.md) has just spent an eleventh type, and the consumers the rule protects do not exist yet — an inventory found intentions for Messagr and Buzz on the roadmap and no interface for either. **A language the table lacks costs the user their assistant on that conversation entirely**, which is severe and is the point: a suggestion that cannot be disclosed is one that should not exist, the same posture ADR 0022 took in refusing an approval whose consent had lapsed a second earlier. The mitigation is that a named, counted refusal is a contribution request an operator can read and fix with one line, where a silent fallback into the wrong language is a sentence nobody ever reads. **The switch has nowhere to live yet**: there is no settings screen in the Companion at all, the `/api/settings/*` routes exist and no route calls them, and the wireframes already list this control among the decided-and-unbuilt — so the switch is a separate piece of work and the disclosure ships on by default before there is a way to turn it off. And the legal ground is narrower than ADR 0019 implies: Article 50 of the AI Act addresses a person interacting with an AI system, while this contact is interacting with a *human* who used one, so its application here is a judgement rather than a given. The project discloses anyway, which is the honest way to hold that position — not because a regulation compels it, but because the alternative is choosing the reading most convenient to us.

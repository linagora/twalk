# Twalk governs what an agent outside it may see and do

Four systems, and the boundary between them is where this project's promises are kept. **Twalk** is the event bus, the Sensor, the bridges and the Companion Gateway: it turns messaging into typed events and it is where consent, the audit trail, approval, disclosure and retention live. **Hermes** — Nous Research's agent runtime, and from here that word means only that — is the brain: it reasons, it remembers, it has skills. **Buzz** is Block's self-hostable Nostr workspace, where the user talks to Hermes and where approvals surface. **The Companion** is the path from nothing to a working deployment, and the place the owner sets it up. The component this repository built and called Hermes is renamed **the persona runtime**, because that is what it does and because the word was already taken.

The persona runtime is **not scaffolding to be removed when the real agent arrives**: it is the enforcement boundary. The consent gate lives in the SDK beside the filter that keeps a persona from being woken by the owner's own traffic, and it is there because a mechanism nobody can forget beats a rule nobody reads. An agent reading the bus from another machine can only be *trusted*; a persona can be *made* to obey. So a persona reaches Hermes by **posting a signed webhook** — Hermes's own declared seam for this, which brings coalescing by conversation, filters evaluated before any model call, and idempotency by delivery id — and what crosses the wire is a **narrow template of named fields**, never the raw event, because Hermes's memory absorbs whatever it is shown and a body copied into `MEMORY.md` never expires. TLS is required by configuration rather than assumed from a mesh network, since the HMAC authenticates the sender and not the content, and the two machines may not stay one machine. Hermes's answer returns **through a Gateway endpoint**, not by publishing to the bus, because the bus has no authentication and "Hermes may publish" means "anything on the network may publish"; and that answer carries **the language it was written in**, or [ADR 0031](0031-the-disclosure-is-written-by-neither-the-model-nor-the-gateway.md)'s disclosure silently falls back to the user's.

**An action that reaches nobody but the user is Hermes's own** — filing, summarising, reminding, drafting — and needs no approval; demanding one would make the agent useless. **An action that reaches a third party comes back through the deployment** and takes the path that already exists: suggestion, approval, disclosure, and a send under the user's own identity (ADR 0025). Hermes runs under a **profile of its own** to begin with, separate from whatever else it does for the operator, because memory is per profile and two writers in one home compound into state neither authored; merging them is the stated objective and not the starting point. `USER.md` may learn from what contacts write **only under `memory.write_approval`**, so that a human stands between an inference and its permanence. Revoking a contact's consent **stops the flow and does not reach what Hermes already learned** — twalk cannot write to another machine's memory, and the consent screen says so, and points at `/journey` where the user can see and delete it. Twalk keeps **no record of what Hermes does outside messaging**: an audit it cannot verify is worse than none, because it would be believed.

Buzz is joined as a **native gateway platform**, the only one of its three integration modes that keeps Hermes's memory, skills, approvals and cron — the other two hand the transport to Buzz, which auto-approves tool permissions. One community, with channels by **kind of conversation** and never by network, since splitting by network would rebuild inside Buzz the fragmentation this project exists to remove. An **explicit allowlist holding the owner's key alone**, because ADR 0011 gives a deployment one owner and an agent holding the user's contacts must not answer to a second principal. And Buzz is a **surface for approval, never its authority**: the Gateway remains the single writer (ADR 0022), because the `approval` table is the only record of what Twalk sent in the user's name and an approval born elsewhere leaves it incomplete exactly when it matters. The Companion configures **the seam and not the agent** — the webhook URL and the HMAC secret, which are Twalk's own configuration — and never Hermes's model, memory or Buzz key, which would mean holding a Nostr private key and writing files on a host Twalk may not own. What it shows of Hermes is a **live read**, so that "Hermes does not answer" and "Hermes was never configured" are two sentences and not one silence (ADR 0024's rule, applied to the one component that is not ours).

Rationale: the owner's stated intent was that Twalk be the event bus that wakes Hermes, which analyses and then suggests **or acts**; what had been built was narrower, and the reconciliation is the split above rather than a retreat by either side. Three beliefs were corrected on the way, and each changed a decision. `SOUL.md` does **not** accumulate a profile of the user — it is a hand-written persona file for the agent, and the framework refuses agent writes to it in code, listing it beside `AGENTS.md` and `CLAUDE.md` as a prompt-injection persistence vector; the file that auto-learns the user is `USER.md`, capped at about 1,375 characters. Buzz is **not** a LINAGORA product, as this glossary claimed; it is Block's, on Nostr, self-hostable, where every message is a signed event on a relay the operator owns. And Hermes is **not** a model plus a prompt convention but a real runtime — MIT, extremely active, and shipping its own messaging adapters for WhatsApp, Signal, Telegram, Matrix, Discord, SMS and more. That last fact is the one that had to be answered rather than avoided: **an agent that can connect to those networks itself does not need Twalk to reach them**. What it needs Twalk for is consent, facets and personas, a single normalised stream that makes cross-network reasoning possible — a WhatsApp message that requires checking a calendar before proposing three meeting times is the example that makes the case — and, in time, skills that teach Hermes how to use Twalk, which is a document rather than a coupling and survives a runtime that ships a thousand commits between patch releases.

The costs are accepted rather than argued away, and the first is a hole this ADR names instead of pretending to close. **Nothing stops Hermes connecting directly to WhatsApp**, and one configuration block would give it the user's conversations with no consent gate, no register, no approval, no disclosure and no retention — and from inside the deployment that is undetectable, so "my agent saw this message" would mean either *through Twalk, governed* or *through its own adapter, ungoverned*, with nothing to tell them apart. Twalk's guarantees hold for events that passed through Twalk and for no others; claiming otherwise would be the kind of unkept promise this project spends its time removing. **Integrating with a runtime at version 0.21.3 that ships over a thousand commits between three-day releases** means pinning a tag and treating the webhook route as the whole contract; anything deeper breaks on a Tuesday. **The seam is asynchronous**, so the synchronous simplicity of a persona calling a model endpoint is given up, and the return path is a thing to build rather than a thing that happens. **The user's messages leave the twalk host** when the two are not the same machine, which is a third place the plaintext exists — after the bus and Hermes's disk — and outside [ADR 0028](0028-a-contacts-words-live-apart-from-the-event-that-identifies-them.md)'s seven days entirely; worse, `SOUL.md`, `MEMORY.md` and `USER.md` are injected into every prompt, so the whole accumulated profile ships to the inference provider on each turn, and only a local model keeps it on the machine. **And the rename is prose-only for now.** `CONTEXT.md` and the ADRs say *persona runtime*; the directory, the crate, twenty-four environment variables and eleven compose references still say `hermes`, which is a wide mechanical refactor deserving its own sequence rather than a paragraph in this one.

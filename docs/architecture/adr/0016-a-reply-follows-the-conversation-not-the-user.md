# A suggested reply follows the conversation's language, not the user's

A persona writes its suggestion in the language of the message it answers, and falls back to the user's own language only when it cannot tell. The user's native language is a stored preference — set in the Companion, held by the Gateway, injected into each persona by the runtime alongside the LLM configuration — and it governs the interface, the explanations, and that fallback; it never governs the text sent to a contact. Detection is the model's job, instructed by the persona's prompt, rather than a detection library: the prompt says to answer in the incoming message's language and to use the user's language when it is ambiguous. Prompts themselves stay in English. The Companion's interface ships in English, French, Italian, Spanish and German, with a missing key falling back to English at runtime and a test that fails on any catalogue whose keys have drifted, so an incomplete contribution is acceptable while a silent divergence is not.

Rationale: a suggestion exists to be sent to someone else. A French user answering an English-speaking contact in French has been handed something they cannot use, so "the user's language" — the intuitive answer, and the one an i18n habit produces — is the wrong axis entirely. The user's language still matters twice, which is why it is stored rather than inferred from the browser: a persona runs in a container and cannot read `navigator.language`. Five interface languages were chosen over two despite the cost being real and stated: the three new ones are not reviewed by native speakers, and their review status is recorded in each catalogue's header and in `CONTRIBUTING.md` rather than shown to a user who could do nothing about it. Marking them in the interface was rejected as advertising a defect to the only person who cannot fix it; leaving the quality unstated was rejected as implying five equally mature languages.

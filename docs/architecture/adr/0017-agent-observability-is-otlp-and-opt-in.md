# Agent observability is OpenTelemetry, off by default, and content is a second decision

A persona and the Hermes runtime emit OpenTelemetry spans following the GenAI semantic conventions: the model call, its latency and token counts, the suggestion produced, the approval or its refusal. Nothing is emitted unless an OTLP endpoint is configured — the same configuration surface as the model itself (ADR 0015) — and a span carries **metadata only** until the operator turns on a second, separately named switch for prompt and completion content. The `traceparent` Twalk already propagates from the Sensor through the persona to the outbound reply is the span's parent, so a trace and the bus event that caused it are joinable. No vendor SDK: Langfuse, which ingests OTLP, is one backend among others.

Rationale: the bus already answers "what did the persona do" — `thinking`, `suggest` and `reply.approved` are durable, replayable and deterministic. What it cannot answer is "why did it propose that", which needs the prompt, the completion and the model's behaviour, and those do not belong in a contract the v1.0 milestone must freeze: they would put message content in a ninth field with a different retention. Emitting the standard rather than a product's SDK follows the project's posture towards mature building blocks — adopt, contribute upstream, preserve the interface — and keeps a persona author free of a tracing dependency. Off by default, and content behind its own switch, because enabling observability would otherwise be a privacy decision disguised as a technical setting: the prompts are the user's messages. Two consequences are stated rather than discovered later — the SDK's consent gate means an unconsented message never reaches the model and therefore never reaches a trace; and the tracing backend's retention becomes a retention period for message content, separate from the bus's, which `docs/architecture/security-model.md` must name.
